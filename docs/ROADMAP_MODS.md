# Совместимость с модами BeamNG — план (не реализовано)

Статус: **ничего из этого ещё не написано.** Сначала нужен собственный soft-body движок, иначе JBeam нечем исполнять.

| Этап | Что | Чем проверяем |
|---|---|---|
| M1 | Soft-body решатель: узлы (масса), балки (пружина/демпфер/предел/прочность), коллизии узлов с землёй/статикой, стабильность при dt ≤ 1/2000 с | юнит-тесты: куб из балок не взрывается, падение, энергия не растёт; бенчмарк узлов/с |
| M2 | Толерантный парсер JBeam (JSON с комментариями, запятые-«хвосты», пропущенные запятые между элементами) | реальные `.jbeam` из ваших модов |
| M3 | Сборка машины из JBeam: `nodes`, `beams`, `slots` (порядок/наследование деталей), `variables`, `flexbodies` (пока только узлы) | загрузка вашего мода, подсчёт узлов/балок, визуал узлов-балок |
| M4 | Колёса/подвеска/мотор/трансмиссия из JBeam (`wheels`, `powertrain`, `engine`, `torqueCurve`) поверх существующих `drivetrain`/`tire` | мод едет, переключает передачи |
| M5 | Меши: `.dae` (COLLADA) + `materials.json` + текстуры (`.dds`/`.png`), привязка flexbody к узлам | визуально |
| M6 | Загрузка мода из `.zip` (`vehicles/<name>/…`), лицензии/авторство в каталоге | ваш мод открывается из архива |
| M7 | Уровни/карты BeamNG (terrain, `.mis`/`items.level.json`) — самый большой объём, отдельно | — |

**Что нужно от вас, чтобы начать M2:** 1–2 мода (лучше простой и средний по сложности) в виде `.zip`. Кладите только то, что вам разрешено использовать. Без реальных файлов парсер будет написан «по памяти о формате», а это именно то, что ломается на настоящих модах.

Честно про границы: «полная» совместимость с BeamNG (весь Lua-слой, контроллеры, электроника, все версии формата) — многолетняя работа; цель — загрузка и езда на типичных машинах-модах.
