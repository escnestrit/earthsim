# earthsim — отдельное приложение (не браузер)

Своя физика (жёсткая **и мягкая, как в BeamNG: узлы + балки**) на Rust + свой рендерер OpenGL 3.3 + Win32-окно. Без внешних зависимостей (только `std`). Карта подгружается **прямо в игре** (OpenStreetMap), скачивать данные заранее не нужно.

## Как получить exe, не устанавливая Rust
В моей песочнице нет Windows-компилятора (сайт Rust там закрыт, обходить я не стал), поэтому exe собирает GitHub:
1. Создайте на github.com пустой репозиторий (бесплатно, можно приватный) и загрузите в него содержимое этой папки (кнопка *Add file → Upload files*, либо `git push`). Папку `target/` загружать не надо.
2. Вкладка **Actions** → слева **build-windows** → **Run workflow** (сборка запускается и сама при каждом push).
3. Через ~5 минут откройте завершённый запуск → внизу **Artifacts → earthsim-windows** → скачайте zip → распакуйте → запустите `start.bat` (или `earthsim.exe`).

Если сборка упадёт — пришлите лог шага «Build earthsim.exe». Оконный слой (`win.rs`) и сетевой клиент WinHTTP (`fetch.rs`) **ни разу не запускались на Windows**: в песочнице они только проходят проверку типов. Первый запуск у вас — это их первый настоящий запуск, ошибки возможны.

## Запуск
* `start.bat` — реальные данные OSM вокруг Минска (нужен интернет).
* `start_offline.bat` — без интернета: тот же стриминг, но из встроенного небольшого набора данных.
* `start_demo.bat` — встроенный синтетический город без стриминга.
* Свои координаты: `earthsim.exe --lat 48.8584 --lon 2.2945` · свой файл сцены: `earthsim.exe --scene scene.json` · кэш: `--cache папка` или переменная `EARTHSIM_CACHE` (по умолчанию папка `cache` рядом с exe) · свой сервер Overpass: переменная `EARTHSIM_OVERPASS`.

## Управление
W/S газ·тормоз·задний ход · A/D руль · **Space ручник** · C камера · [ ] время суток · L фары · **R респавн на старте + ремонт** · U поставить на колёса + ремонт · T антибуксовка · B ABS · H HUD · F1 подсказка · **F2 телепорт** (Минск → Париж → Нью-Йорк → Токио → Лондон → Берлин) · **F3 мягкая/жёсткая физика** · F11 полный экран · Esc выход

## Потоковая подгрузка Земли
Земля разбита на тайлы Web-Mercator z15 (около 1.2 км на экваторе, по всему миру до 85° широты). Вокруг машины всегда загружен радиус ~1.5 км, дальше 2.4 км тайлы выгружаются. Для каждого тайла:
* сначала дисковый кэш; если нет — запрос к Overpass (один запрос за раз, не чаще 1 раза в 1.5 с, с паузой и экспоненциальным откатом при ошибках, ответ кэшируется на диске на 30 дней; при недоступной сети используется устаревший кэш);
* разбор данных → здания (с паспортом: статус «PROCEDURAL_APPROXIMATION», происхождение высоты), дороги, деревья → меши строятся в фоновом потоке, в главном потоке только загрузка в GPU (не больше 2 тайлов за кадр);
* коллизии зданий и деревьев добавляются/убираются вместе с тайлом;
* «плавающее начало координат»: при удалении на 4 км от начала система координат переносится, без перекачки данных;
* после телепорта машина стоит, пока не придёт карта вокруг неё, затем встаёт на ближайшую дорогу шире 5 м.

HUD показывает загруженные/загружаемые тайлы, ошибки, число сетевых запросов и попаданий в кэш, последнюю ошибку и «© OpenStreetMap contributors (ODbL)».

**Честные ограничения.** Публичные серверы Overpass — общий ресурс с лимитами; запросы вежливые, но для долгих поездок поднимите свой сервер. Первый тайл приходит за несколько секунд, весь радиус — за минуту-две. Рельефа нет (плоская земля; DEM — следующий шаг). Мультиполигоны и `building:part` не обрабатываются, туннели пропускаются. Парсер написан под формат Overpass JSON и проверен только на встроенном образце — на настоящем ответе сервера он ещё не пробовался.

## Мягкая физика (как в BeamNG, но проще)
Кузов — решётка из 44 узлов и 242 балок (пружина + демпфер), подвеска — тоже балки (пружина-амортизатор, ограничители хода, рычаги), шины, тормоза, ручник, ABS и трансмиссия — те же модели, что у жёсткой машины (шина считается на узле ступицы). Балки **текут** (остаются деформированными, зоны смятия слабее салона) и **рвутся**. Удар о здание/дерево неупругий, энергию гасит кузов. Модель кузова на экране деформируется вместе с решёткой; HUD показывает «BODY DAMAGE» и число порванных балок.
Проверено тестами (машина против жёсткой модели): разгон 0–100 за 9.48 с против 9.42; торможение со 100 км/ч 38 м против 37; боковое ускорение в повороте ±5%; стоит на пружинах с правильной нагрузкой (14 224 Н = вес) без дрейфа и повреждений; 60 с случайной езды — без расхождений и повреждений; лобовой удар 50 км/ч: нос сминается ~0.45 м, поглощается ~95 кДж, пик замедления ~36 g, узлы не проходят сквозь стену, салон цел; сильнее удар — больше повреждений, ничего не «взрывается».
**Честно:** это **не** JBeam из BeamNG и не его модели — решётка задана в коде; жёсткость, пределы текучести и зоны смятия подобраны мной под правдоподобные цифры, а не откалиброваны по краш-тестам. Нет самоконтакта узлов, отлетающих деталей, пожара, деформации шин; руль упрощён (угол задаётся, а не рычагом). Загрузка JBeam/DAE/zip-модов из BeamNG **не сделана** (план в `docs/ROADMAP_MODS.md`; нужны ваши моды для проверки). Стоимость: ~0.16 мс процессорного времени на 1 мс игрового (~16% одного ядра) — на слабом ПК F3 вернёт жёсткую модель.

## Ручник
Тормозной момент на задней оси с залипанием колеса. Без газа колёса блокируются, хвост уходит в занос, машина останавливается. С газом момент уступает двигателю (−75% при полном газе), задние шины теряют ~45% сцепления, пока ручник зажат — занос держится, машина не глохнет. Это **помощь для дрифта**, а не чистая физика; константа `HANDBRAKE_GRIP_LOSS`. На уклоне 10° ручник держит машину.

## Что проверено (`cargo test --release`: 134 теста, все проходят в песочнице на Linux)
* **phys** (49): математика, шина, трансмиссия, подвеска, ручник, столкновения, детерминизм, 180 000 шагов случайных воздействий; ядро мягкого тела (частота колебаний, энергия, текучесть, разрыв, контакт, трение); мягкая машина (см. выше).
* **scene** (16): JSON, сцена, меши, спавн, езда по демо-городу.
* **world** (43): геодезия, тайлы, разбор OSM (сверка с эталоном на Python), этап A зданий, кэш, фетчеры, **стример** (загрузка вокруг машины, кэш без запросов, устаревший кэш, откат при ошибках без спама, ограничение частоты, выгрузка, перенос начала координат без перекачки, телепорт, остановка потоков) — всё на имитации сервера.
* **app** (26): камера/HUD/ввод, командная строка, потоковая игра (машина ждёт карту и встаёт на дорогу, телепорт, перенос начала), мягкая машина в игре (F3, повреждения, ремонт), деформируемый меш.
* **Рендер** прогнан без окна через Mesa EGL (OpenGL 4.5 core, llvmpipe): шейдеры, тайлы из потока, деформированный кузов. На реальной видеокарте/Windows-драйвере — **не проверялось**. MSAA нет.

## Структура
`crates/phys` — физика (жёсткая и мягкая) · `crates/scene` — JSON, сцена, меши · `crates/world` — геодезия, тайлы, OSM, кэш, сеть, стример · `crates/app` — игра, рендер, Win32 · `python/` — офлайн-конвертер OSM→scene.json · `docs/ROADMAP_MODS.md` — план совместимости с BeamNG · `.github/workflows/build.yml` — сборка exe на GitHub.
